# PoC 03 — 地形系统

- **依赖**：p01 六角格地图
- **被依赖**：p02（移动），p05（战斗）

## 验证目标

实现多种地形类型影响移动力与防御，验证地形对游戏策略的实质性影响。

## 地形类型

| 地形 | 移动消耗 | 防御加成 | 全掩体 | 特殊 |
|------|---------|---------|--------|------|
| 平原 | 1 | 0 | 否 | 无 |
| 村庄 | 1 | +1 | 否 | 无 |
| 城镇据点 | 2 | +2 | 否 | 无 |
| 河流 | 4 | 0 | 否 | 可通过 |
| 核心据点 | 3 | +4 | 是 | 仅突击兵种可进入 |

## 数据模型

```
TerrainType: enum { PLAIN, VILLAGE, TOWN, RIVER, CORE_FORT }

TerrainProps {
  moveCost: number
  defenseBonus: number
  isFullCover: boolean
  isCore: boolean
}

// 地形配置表
TERRAIN_CONFIG: Record<TerrainType, TerrainProps>
```

## 实现步骤

1. 定义地形枚举和属性映射表
2. 实现地形 → 颜色/样式的视觉映射（平原绿、村庄褐、河流蓝等）
3. 地形配置外置（JSON/常量文件，与渲染层分离）
4. 生成预设地形布局（JSON 中定义每格地形类型，手动编辑 JSON）
5. 验证不同地形对移动范围的影响（见 PoC 02）
6. 验证不同地形对防御的影响（见 PoC 05）

## 关键技术

- 数据驱动：地形属性集中配置，不硬编码
- 视觉-机制一致性：地形颜色传递功能含义（绿色=安全、蓝色=阻隔、褐色=掩护）
- 可扩展：添加新地形只需新增枚举值和属性配置

## 验收标准

- [ ] 5 种地形在网格上可区分渲染
- [ ] 地形消耗正确影响 BFS 移动范围
- [ ] 防御加成正确影响命中率计算
- [ ] 全掩体阻挡非突击兵种的远程攻击
- [ ] 新增一种地形只需改配置文件

## 实现记录

**文件**：`examples/p03-terrain/index.html`

**状态**：✓ 验收标准全部通过

**实际实现**：
- 5 种地形以对象常量表定义（`PLAIN/VILLAGE/TOWN/RIVER/CORE_FORT`）
- 伪随机生成（seeded random） + 手动覆盖（中心核心据点、河流线、城镇/村庄固定位置）
- 每种地形有唯一图标字符（◆ ■ • ≈）辅助识别
- 图例显示所有地形颜色和名称
- 点击格子显示详细属性：移动消耗、防御加成、全掩体标记
- 地形颜色按功能含义划分（绿=安全、蓝=阻隔、褐=掩护、红=关键）

**偏差**：
- 地形布局使用内联数组而非独立 JSON 文件 —— 原型阶段内联更方便迭代
- 未实现"新增地形只需改配置文件" —— 当前配置在代码中，但迁移到 JSON 只需提取常量表

**经验**：
- 颜色+图标双重编码对地形识别有帮助，色盲友好
- 手动覆盖特定格比全随机生成更实用（可设计有战术意义的地图）
- 地形属性集中定义在常量表中，新增地形确实只需加一行
