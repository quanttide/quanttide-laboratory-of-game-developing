# PoC 11 — 执行阶段

## 验证目标

签署命令后，单位自动执行命令、动态战报推送、不可干预。

## 执行阶段流程

```
签署命令 → 执行开始 → [循环] 单位动画移动 → 战报推送 → 检查完成条件
  → 全部完成/超时 → 结算画面
```

## 执行规则

- 单位按照命令自动移动/攻击
- 玩家不可干预执行过程（无暂停/取消/重选）
- 战报每 8 秒推送一条
- 执行阶段总时长根据行动数量动态计算
- 支持加速模式（2x/3x 加速）

## 战报系统

```
BattleReport {
  timestamp: string          // 战报时间
  content: string            // 战报文本
  type: 'MOVEMENT' | 'COMBAT' | 'INTEL' | 'LOGISTICS'
  relatedUnit?: string
  relatedCoords?: [q, r]
}
```

示例：
- MOVEMENT: "1纵 先头部队已抵达龙王店外围"
- COMBAT: "6纵 与敌 75 师在铁佛寺交火，毙敌 30 余"
- INTEL: "侦察队报告：邱清泉部 3 个团正向东运动"
- LOGISTICS: "弹药消耗：炮弹 200 发，枪弹 3000 发"

## 结算评分

| 条件 | 等级 | 描述 |
|------|------|------|
| 目标全部达成 | 大获全胜 | 所有作战目标按时完成 |
| 目标部分达成 | 部分成功 | 主要目标完成，次要目标未达成 |
| 时间耗尽 | 战斗中止 | 未完成目标但未被击溃 |
| 防线崩溃 | 战斗失败 | 核心目标丢失或部队被全歼 |

## 实现步骤

1. 实现执行阶段状态机（等待 → 执行中 → 加速 → 完成）
2. 实现单位自动动画（按顺序逐个移动/攻击）
3. 实现战报生成器和推送队列
4. 实现战报 UI（滚动的无线电消息流）
5. 实现完成条件检测
6. 实现结算画面
7. 实现加速/减速控制

## 验收标准

- [ ] 签署后单位自动执行命令
- [ ] 执行过程中玩家不可干预
- [ ] 战报每 8 秒自动推送
- [ ] 所有单位行动完成后显示结算画面
- [ ] 支持 2x 加速
- [ ] 结算等级正确反映完成情况
